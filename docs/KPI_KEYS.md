# 計画評価指標の日本語キー

`T_PlanKpis.KpiKey`とAPIの評価値キーには、次の日本語名を使用する。計算式・単位・評価の方向は変更しない。

| 旧キー | 保存する日本語キー | 単位 |
| --- | --- | --- |
| late_orders | 納期遅れ | 件 |
| total_lateness_min | 遅れ時間の合計 | 分 |
| setup_min | 段取り時間 | 分 |
| makespan_min | 最終完了 | 分 |
| utilisation_pct | 平均負荷率 | % |
| scheduled_tasks | 割付済みタスク | 件 |
| unscheduled_tasks | 未割付タスク | 件 |

## 保存と既存データ

- 自動計算・手動編集による再評価と、Python・SQLのデモデータは日本語キーで保存する。
- 既存計画のコピーも、日本語キーで保存する。
- 保存済みKPIのAPI取得・計画ボード・計画比較では、旧英語キーを共通処理`app/engine/kpi_keys.py`で日本語に変換する。読込だけではDBを書き換えない。
- 同一計画に新旧両方の指標がある場合は、日本語側の値を優先する。
- 計算設定の重み`lateness`・`setup`・`makespan`などは別の項目のため変更しない。

## 既存DBの保存値を一括変換する場合

1. バックエンドと計算ワーカーを停止する。
2. SQL Serverの対象DBを選択し、[変換SQL](../DataBase/query/convert_plan_kpi_keys_to_japanese_sqlserver.sql)を手動実行する。
3. 更新後のバックエンド・フロントエンドを使用し、評価値の表示・比較を確認する。

このSQLは7指標のキーだけを変換し、評価値や計画IDを変更しない。新旧両方の行がある場合は旧行を削除して日本語行を残す。繰り返し実行できる。

新規DBは、従来の作成SQL・スキーマSQL・更新済みデモデータSQLの順で作成する。`KpiKey`は既存の`NVARCHAR(50)`で日本語を保存できるため、カラム定義の変更は不要。
